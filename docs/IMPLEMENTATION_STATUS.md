## M00 — Discovery and setup

**Findings**
- Repository contained only the build plan (`Master-Plan.MD`). No existing
  code, framework or seamless-texture tool. A formatted copy of the plan lives
  at `docs/MASTER_BUILD_PLAN.md`.
- Owner has created an R2 bucket and a Supabase project linked to GitHub
  (2026-10-16). Credentials have not been shared and should not be pasted into
  chat; they go into host environment variables at deploy time.
- Owner has local textures, models and a seamless texture tool; integration
  pending delivery of a sample pack and the tool source.

**Built**
- Next.js 16.4.2 + React 19.3 + TypeScript 5.9 (strict), Tailwind CSS 4.3,
  ESLint 9 flat config (`eslint-config-next`), Vitest 4, Playwright 1.56.1
  (matches the pre-installed Chromium), pnpm 10, Node 22.
- Initial design tokens and type scale (replaced in M01, see ADR 0007).
- `/api/health`, E2E server harness (`scripts/e2e-server.ts`).
- GitHub Actions CI: lint → typecheck → unit/integration (with a Postgres 16
  service) → build → Playwright.
- Docs: architecture, design system, ADRs 0001–0006.

**Verified**: PGlite supports roles, `SET LOCAL ROLE`, RLS policies,
`set_config`, full-text search, `pg_trgm`, array and JSONB parameters — the
basis for ADR 0002. A local Postgres 16 server is used for driver tests.

**Toolchain notes**
- TypeScript 7 (native port) is the npm `latest` but is pinned to 5.9 for
  Next.js/typescript-eslint compatibility.
- Next.js 16 removed `next lint`; `pnpm lint` runs ESLint directly.
- `pnpm typecheck` runs `next typegen` first so `PageProps`/`LayoutProps`
  globals exist.

## M02 — Infrastructure

**Built**
- `src/lib/env.ts`: Zod-validated server config; local fallback secret per data dir.
- Database (`src/lib/db`): one interface over PGlite (local) and postgres.js
  (Supabase/Postgres); request contexts `public`/`user`/`service` enforced with
  `SET LOCAL ROLE lp_anon|lp_authenticated` + claims; `Tx` runner so services
  never nest transactions; migration runner with checksums.
- Migrations (`supabase/migrations`): full data model from plan §7 (users,
  sessions, rate limits, licences, categories, tags, creators, assets + files +
  tags/creators/dependencies, collections, shaders, starters, tutorial
  creators, tutorials, external resources, tools, site settings, presets,
  download counters, audit log, upload sessions, import jobs, contact
  messages), FTS (`tsvector` incl. tag names) + trigram, RLS policies on every
  table, publish guards (known licence + attestation enforced in the DB),
  reference licences/categories/tags.
- Auth (`src/lib/auth`): scrypt passwords, opaque session tokens (hash stored),
  HttpOnly/SameSite=Lax/Secure cookie, sliding expiry, DB rate limits, origin
  checks, open-redirect-safe `next`, first-admin setup (token-gated on hosted
  DBs), `pnpm admin:create`.
- Storage (`src/lib/storage`): `AssetStorage` with private/public buckets;
  `LocalFilesystemStorage` (HMAC-signed upload/read URLs) and `R2Storage`
  (S3 API, presigned PUT signing content-type + content-length, single- or
  two-bucket mode); server-built keys only; safe filenames/Content-Disposition.
- Uploads (`src/lib/assets`): signed upload sessions → browser PUT → verify
  (size, SHA-256, magic bytes, purpose allow-list, ZIP entry inspection, image
  metadata via sharp, glTF stats) → file under the asset; dedupe by checksum;
  expiry sweeper; redacted audit log.
- Formats (`src/lib/formats`): dependency-free GLB writer, glTF validator +
  statistics (unique vs instanced triangles, draw calls, world bounds, UV
  channels, embedded image sizes, unsupported required extensions), image
  header sizes, faceted primitive builders.
- Routes: `/api/auth/{login,logout,setup}`, `/api/admin/uploads`,
  `/api/admin/uploads/[id]/complete`, `/api/storage/{upload,object}` (local
  only), `/files/[...key]` (public bucket only), `/api/health` (DB check).
- Pages: `/auth/login`, `/auth/setup`, admin shell + dashboard.
- Scripts: `db:migrate`, `db:seed`, `db:reset`, `admin:create`, `vercel-build`.
- Docs: `.env.example`, `docs/DEPLOYMENT.md` (Supabase, R2 buckets/CORS/token,
  Vercel, secrets, first admin), `vercel.json`.

**Verified**
- RLS suite (15 cases × PGlite and Postgres 16): anonymous sees published only,
  cannot write or read accounts/operational tables; editors draft but cannot
  publish; admins publish only with a known licence and attestation; presets
  private per user; audit actor cannot be forged; FTS over tag names.
- Migrations applied by a **non-superuser CREATEROLE owner on a fresh
  Postgres 16 cluster** (simulating Supabase's `postgres` role), which can then
  assume both RLS roles. Re-running is a no-op.
- Upload pipeline (12 cases × 2 drivers): GLB stats, image alpha, dedupe,
  disguised executable rejected and staged bytes deleted, size mismatch,
  ZIP with `.exe`, wrong purpose, oversize, cross-user completion, anonymous
  access, expiry sweep, audit redaction.
- Storage contract (7 cases × local, R2 two-bucket, R2 single-bucket) against
  an S3-compatible server (moto), including real presigned PUT/GET.
- E2E: sign-in errors, cookie flags, dashboard, sign-out, setup lock, open
  redirect refused; journey 10 — unauthenticated upload signing 401/403,
  cross-site POST with a valid session 403, forged storage tokens 403,
  private/unknown paths under `/files` 404.

**Bugs found and fixed by the tests**: postgres.js double-encoded JSON params
(convention now `$n::text::jsonb`); nested service queries inside a user
transaction deadlocked PGlite (introduced the `Tx` runner); a migration that
silently swallowed a failed role grant (replaced by an explicit, loud one).

**Not yet verified against the owner's real services**: Supabase pooler and
Cloudflare R2 themselves (no credentials in this environment). The R2 adapter
is verified against an S3-compatible server; DEPLOYMENT.md lists the checks to
run after the first deploy.

## M03 — Asset CMS and public catalogue

**Built**
- Asset pipeline (`src/lib/assets`): FBX → GLB conversion (three.js
  FBXLoader in Node, textures resolved by name), software-rasterised model
  thumbnails, image thumbnails, 32–256 px nearest-neighbour variants, facets
  recomputed from real file metadata, publish checklist, bundle ZIP (files +
  LICENSE + README + manifest with checksums, deterministic), unpublish that
  removes public copies at once, privacy-preserving download counts.
- Public catalogue: `/assets` and `/textures` (full-text + prefix + typo
  search, facet filters with counts, chips, sort, grid/list, pagination,
  noindex on filtered URLs); detail pages with an orbitable GLB viewer
  (shaded/unlit/wire, grid, turntable), a texel-accurate texture viewer
  (zoom, 3×3 tiling, nearest/bilinear, backdrop, texel readout), ZIP and
  per-file downloads, a credit dialog when the licence requires attribution,
  licence rights, specs, tags, related items, JSON-LD; `/collections` and pack
  pages with counted pack downloads; ⌘K palette searches the catalogue;
  sitemap lists published assets and collections; home page uses live data.
- Admin CMS: asset list (status/problem tabs, search, type), draft creation,
  editor (details, licence and rights with attestation stamped by person and
  date and cleared when the licence changes, files with signed uploads,
  previews, primary/include/delete, automatic previews, publish checklist,
  publish/republish/unpublish/delete, history), collections editor with an
  asset picker and pack builds, bulk import wizard, contact inbox (takedowns
  first), audit log, dashboard quick links. Editors draft and submit for
  review; admins publish.
- Bulk import (`src/lib/assets/import.ts`, `/admin/import`,
  `pnpm import:assets`): folder grouping that matches the owner's exports,
  JSON/CSV manifests, dry-run validation (references, slugs, duplicates by
  SHA-256), drafts only, report + `import_jobs` record. Guide:
  `docs/IMPORTING.md`.
- Public contact/takedown form (rate limited per hashed address, honeypot).
- Migrations 004 (collection download counts) and 005 (staff-only
  `user_names` view for audit trails).
- Demo library: 11 textures, 10 models and 2 collections seeded through the
  real pipeline (`pnpm db:seed`, also used by E2E).

**Owner assets (local only)**: all 72 Tripo FBX models and the 10 wood
textures were imported into the local development library as drafts with
`pnpm import:assets`: 82 created, 0 conversion warnings, 72 FBX converted to
GLB with embedded textures, every asset with a thumbnail. Provenance for the
models is recorded factually ("Exported from Tripo AI … plan and licence terms
not yet confirmed"); no licence is set and rights are not confirmed. Nothing
is in production yet: once the live site is deployed the owner imports from
**Admin → Import** (or the CLI with production env vars) and publishes each
asset after choosing its licence.

**Verified**
- Integration (PGlite + Postgres): seeded catalogue counts, search (full-text,
  prefix, typo), facet counting, sorting/paging, garbage parameters, download
  counting and dedupe, licence-blocked downloads, unpublish removes public
  copies, publish rules, FBX pipeline (with and without textures),
  collections (refuses unpublished members, NOTICE per asset, listing,
  search, pack download counts), attestation rules, editor review flow,
  admin lists, staff-only names, audit visibility, contact messages, bulk
  import (drafts only, FBX → GLB, audit, dedupe on re-run, reference errors).
- Unit: import planning on the owner's real folder layout, CSV/JSON
  manifests, origin checks behind proxies and in dev, Markdown sanitising.
- E2E: journey 1 (search with a typo, filter chips, model viewer, ZIP
  contents, texture tiling/zoom, 308/404 status codes, collections, command
  palette, sitemap); journey 2 (create → upload → content rejection →
  details → licence + attestation → publish → visitor download → unpublish →
  404 → history); journey 3 (collection pack build); bulk import wizard;
  contact form → admin inbox; axe WCAG 2.2 AA on 10 public pages (CRT on and
  off) and 8 admin pages.

**Bugs found and fixed**: a site-wide loading boundary turned missing-asset
404s and section redirects into 200s (moved into listing route groups); the
nested 404 doubled the header; toast server snapshot caused a render loop
warning; ON/OFF switches failed WCAG 2.5.3; the migration runner traced the
whole project into the server bundle; the origin check rejected sign-in when
Next dev normalised the host; changing a licence kept a stale attestation; a
restored Turbopack dev cache put browsers into a reload loop (dev cache
disabled); two processes could open the same local PGlite directory (lock
file added).

**Known limitations**
- Collections, catalogue and admin work with up to thousands of assets; the
  admin list and import planner are not yet tuned beyond that.
- Republishing is manual after changing files or the licence of a published
  asset (the editor says so).
- Asset dependencies and creator credits exist in the schema and on detail
  pages but have no editor UI yet (planned with M07 Workshop).
