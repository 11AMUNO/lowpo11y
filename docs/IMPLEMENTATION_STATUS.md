## M00 — Discovery and setup

**Findings**
- Repository contained only the build plan (`Master-Plan.MD`). No existing
  code, framework or seamless-texture tool. A formatted copy of the plan lives
  at `docs/MASTER_BUILD_PLAN.md`.
- Owner has created an R2 bucket and a Supabase project linked to GitHub
  (2026-10-16). Credentials have not been shared and should not be pasted into
  chat; they go into host environment variables at deploy time.
- Owner has local textures, models and a seamless texture tool; integration
  pending delivery of a sample pack and the tool source.

**Built**
- Next.js 16.4.2 + React 19.3 + TypeScript 5.9 (strict), Tailwind CSS 4.3,
  ESLint 9 flat config (`eslint-config-next`), Vitest 4, Playwright 1.56.1
  (matches the pre-installed Chromium), pnpm 10, Node 22.
- Initial design tokens and type scale (replaced in M01, see ADR 0007).
- `/api/health`, E2E server harness (`scripts/e2e-server.ts`).
- GitHub Actions CI: lint → typecheck → unit/integration (with a Postgres 16
  service) → build → Playwright.
- Docs: architecture, design system, ADRs 0001–0006.

**Verified**: PGlite supports roles, `SET LOCAL ROLE`, RLS policies,
`set_config`, full-text search, `pg_trgm`, array and JSONB parameters — the
basis for ADR 0002. A local Postgres 16 server is used for driver tests.

**Toolchain notes**
- TypeScript 7 (native port) is the npm `latest` but is pinned to 5.9 for
  Next.js/typescript-eslint compatibility.
- Next.js 16 removed `next lint`; `pnpm lint` runs ESLint directly.
- `pnpm typecheck` runs `next typegen` first so `PageProps`/`LayoutProps`
  globals exist.

## M02 — Infrastructure

**Built**
- `src/lib/env.ts`: Zod-validated server config; local fallback secret per data dir.
- Database (`src/lib/db`): one interface over PGlite (local) and postgres.js
  (Supabase/Postgres); request contexts `public`/`user`/`service` enforced with
  `SET LOCAL ROLE lp_anon|lp_authenticated` + claims; `Tx` runner so services
  never nest transactions; migration runner with checksums.
- Migrations (`supabase/migrations`): full data model from plan §7 (users,
  sessions, rate limits, licences, categories, tags, creators, assets + files +
  tags/creators/dependencies, collections, shaders, starters, tutorial
  creators, tutorials, external resources, tools, site settings, presets,
  download counters, audit log, upload sessions, import jobs, contact
  messages), FTS (`tsvector` incl. tag names) + trigram, RLS policies on every
  table, publish guards (known licence + attestation enforced in the DB),
  reference licences/categories/tags.
- Auth (`src/lib/auth`): scrypt passwords, opaque session tokens (hash stored),
  HttpOnly/SameSite=Lax/Secure cookie, sliding expiry, DB rate limits, origin
  checks, open-redirect-safe `next`, first-admin setup (token-gated on hosted
  DBs), `pnpm admin:create`.
- Storage (`src/lib/storage`): `AssetStorage` with private/public buckets;
  `LocalFilesystemStorage` (HMAC-signed upload/read URLs) and `R2Storage`
  (S3 API, presigned PUT signing content-type + content-length, single- or
  two-bucket mode); server-built keys only; safe filenames/Content-Disposition.
- Uploads (`src/lib/assets`): signed upload sessions → browser PUT → verify
  (size, SHA-256, magic bytes, purpose allow-list, ZIP entry inspection, image
  metadata via sharp, glTF stats) → file under the asset; dedupe by checksum;
  expiry sweeper; redacted audit log.
- Formats (`src/lib/formats`): dependency-free GLB writer, glTF validator +
  statistics (unique vs instanced triangles, draw calls, world bounds, UV
  channels, embedded image sizes, unsupported required extensions), image
  header sizes, faceted primitive builders.
- Routes: `/api/auth/{login,logout,setup}`, `/api/admin/uploads`,
  `/api/admin/uploads/[id]/complete`, `/api/storage/{upload,object}` (local
  only), `/files/[...key]` (public bucket only), `/api/health` (DB check).
- Pages: `/auth/login`, `/auth/setup`, admin shell + dashboard.
- Scripts: `db:migrate`, `db:seed`, `db:reset`, `admin:create`, `vercel-build`.
- Docs: `.env.example`, `docs/DEPLOYMENT.md` (Supabase, R2 buckets/CORS/token,
  Vercel, secrets, first admin), `vercel.json`.

**Verified**
- RLS suite (15 cases × PGlite and Postgres 16): anonymous sees published only,
  cannot write or read accounts/operational tables; editors draft but cannot
  publish; admins publish only with a known licence and attestation; presets
  private per user; audit actor cannot be forged; FTS over tag names.
- Migrations applied by a **non-superuser CREATEROLE owner on a fresh
  Postgres 16 cluster** (simulating Supabase's `postgres` role), which can then
  assume both RLS roles. Re-running is a no-op.
- Upload pipeline (12 cases × 2 drivers): GLB stats, image alpha, dedupe,
  disguised executable rejected and staged bytes deleted, size mismatch,
  ZIP with `.exe`, wrong purpose, oversize, cross-user completion, anonymous
  access, expiry sweep, audit redaction.
- Storage contract (7 cases × local, R2 two-bucket, R2 single-bucket) against
  an S3-compatible server (moto), including real presigned PUT/GET.
- E2E: sign-in errors, cookie flags, dashboard, sign-out, setup lock, open
  redirect refused; journey 10 — unauthenticated upload signing 401/403,
  cross-site POST with a valid session 403, forged storage tokens 403,
  private/unknown paths under `/files` 404.

**Bugs found and fixed by the tests**: postgres.js double-encoded JSON params
(convention now `$n::text::jsonb`); nested service queries inside a user
transaction deadlocked PGlite (introduced the `Tx` runner); a migration that
silently swallowed a failed role grant (replaced by an explicit, loud one).

**Not yet verified against the owner's real services**: Supabase pooler and
Cloudflare R2 themselves (no credentials in this environment). The R2 adapter
is verified against an S3-compatible server; DEPLOYMENT.md lists the checks to
run after the first deploy.

## M04 — Initial processing tools

**Built**
- **T01 Seamless** (`/tools/seamless`): the owner's 11AM-Seamless v2,
  vendored unmodified in `vendor/11am-seamless`, ported to TypeScript
  (`src/lib/processing/seamless/engine.ts`) and rebuilt in React with the
  original app's behaviour: collections from dropped folders, per-file
  settings, the 01–04 pipeline rack, split and tile previews, seam score,
  PNG/JPG/WEBP export and a batch ZIP laid out size/collection/file.
- **T02 Retro texture converter** (`/tools/texture-converter`): exact output
  sizes (presets 32–512, custom, long side; crop, pad or stretch), nearest or
  smooth resampling, brightness/contrast/saturation/gamma, seeded grain,
  per-channel bit depth (RGB555, 565, 444, 332 or custom), adaptive
  median-cut or locked palettes (lock the current one, paste hex or a GIMP
  `.gpl`, save as `.gpl`), 2×2/4×4/8×8 Bayer, blue-noise and
  Floyd–Steinberg dithering (errors wrap at the edges so tiles stay
  seamless), alpha kept or cut to 1 bit, five starting presets, before/after
  and tile previews, undo/reset, settings remembered, keys D and T. The page
  states that colour reduction is a visual effect and doesn't enforce any
  console's VRAM or CLUT limits.
- **Batch resizer** (`/tools/resizer`): drop folder trees or pick files or a
  folder; long side, exact (crop/pad/stretch) or percentage sizes,
  power-of-two rounding, nearest or smooth sampling, keep the format or write
  PNG/JPG/WEBP; planned output sizes show before resizing; parallel workers
  with progress and stop; per-file save and a ZIP that keeps folder paths.
- Shared processing core (ADR 0008): pure RGBA resampling (premultiplied
  triangle filter), quantising, ordered and blue-noise thresholds,
  void-and-cluster blue noise, and a deterministic PNG encoder, so a
  download holds exactly the previewed pixels. Shared tool code: viewport,
  file decoding, folder drop reading (`src/features/tools/shared`).
- Format validation: drop zones check type and size (64 MB) and decode
  limits (4096² converter, 8192² resizer and Seamless); damaged or
  unsupported files get a plain error, and the resizer marks them
  unreadable and leaves them out of the ZIP.
- The tools registry marks Seamless, the converter and the resizer as
  available; the tools page, menu and sitemap follow it.

**Verified**
- Seamless regression: the port runs beside the original engine in Chromium
  over 29 settings × 4 inputs on the main thread and in a worker: 232
  comparisons, all byte-identical. A downloaded PNG equals the original
  engine's output.
- Unit: resampling (exact sizes for every fit, flat colours stay flat,
  no dark fringes against transparency), bit replication, median cut,
  palette parsing, blue-noise ranks, every dither mode stays inside its
  palette, locked palettes, RGB555 grid, seed determinism, presets, resize
  planning, PNG round trips including semi-transparent pixels.
- E2E: converter output equals the core run in Node on the same input,
  byte for byte, at a non-square non-power-of-two size with alpha; the
  same settings give the same file twice; presets, palette lock, cutout,
  undo, remembered settings and a damaged file. **Journey 4**: texture →
  Seamless → converter → the PNG equals the core's output and every
  sampled texel of the on-screen preview. Resizer: a folder tree with a
  text file and a damaged PNG → ZIP with folder paths, exact sizes, alpha
  kept, JPG stays JPG; settings changes mark files stale; pad leaves
  transparent margins. axe WCAG 2.2 AA on all three tools, empty and with
  files loaded. Layout: no overlapping panels at phone width, and the
  workspace never scrolls the page on desktop.

**Bugs found and fixed**: on phones the tool panels overlapped and covered
each other's buttons (the workspace grid was locked to the window height);
screen-reader-only labels deep in a scrolled panel made the Seamless page
scroll by 76px on desktop (the studio layout is now the positioning
context); a test helper that ran one assertion per pixel made a test take
19 s instead of 3 s.

**Known limitations**
- Decoding goes through the browser's premultiplied canvas: alpha values
  are exact, but the colour of semi-transparent input pixels can move by a
  few levels before processing (ADR 0008; a JS PNG decoder is an M09
  candidate).
- The converter handles one image at a time; batch conversion arrives with
  the Workshop (M07).
- "Copy/share recipe" from the plan's tool checklist isn't built yet:
  settings are remembered per browser but can't be exported. Planned with
  Workshop presets (M07).

## M05 — Advanced tools

All eight tools in the registry are now available: Seamless, the retro
converter, the batch resizer, and the five below. Each runs locally in the
browser, keeps settings (never images) in the browser, and has a CC0 sample.

**Built**
- **Palette generator** (`/tools/palette`): extract 4–256 colours (median
  cut refined by k-means in OKLab) with locked colours kept exactly; list
  and inspector (hex, RGB, name, reorder, duplicate, remove); OKLCh
  harmonies; colour-vision simulation (Machado 2009) with confusable pairs,
  also applied to the preview; preview of an image in the palette with
  dithering and PNG download; GPL, HEX, LOWPO11Y JSON and PNG swatch import
  and export; eight original starter palettes (none presented as an
  official hardware palette); undo; the palette is remembered.
- **Texture atlas builder** (`/tools/texture-atlas`): tiles from files,
  folders or drops; rename, reorder, rotate, trim, fill; optional resize to
  one tile size; MaxRects (optional 90° rotation) or grid packing; padding,
  border and edge extrusion; auto (tight, square, power of two) or manual
  size with overflow reported; UVs for a top-left or bottom-left origin
  with Blender/Godot/Unity presets and optional half-texel inset; PNG,
  JSON, CSV or ZIP; filtering and mipmap notes.
- **Model inspector** (`/tools/model-inspector`): .glb, or .gltf with its
  .bin and textures; statistics from the file (scene vs unique triangles,
  estimated and measured draw calls, materials, textures, skins, morphs,
  animations, UVs, normals, size); shaded/unlit/wire/normals, flat shading,
  grid, axes, bounds, backgrounds and lights; clip play/pause/scrub;
  screenshot; report JSON; checks for NPOT and oversized textures, missing
  normals, scale and draw calls; Draco/meshopt/KTX2 files explained instead
  of crashing; GPU resources freed on every unload, with live counts.
- **Bitmap font generator** (`/tools/bitmap-font`): reads TTF/OTF cmaps,
  names, embedded licence text and embedding permissions; character presets,
  typed characters and U+ ranges with missing glyphs listed; 1-bit or
  smooth edges, outline and shadow (exact pixel dilation in 1-bit mode),
  spacing, line height, padding, kerning from the browser's shaping;
  multi-page output; AngelCode BMFont text and JSON; the preview is drawn
  from the generated files by LOWPO11Y's BMFont renderer. Sample font:
  "LOWPO11Y Pixel", a 5×7 font drawn for the project (CC0).
- **Decal and cutout maker** (`/tools/decal`): rotate, flip, crop and trim
  to subject; key by colour (OKLab distance, several colours, background
  guessed from the corners, pick from the image) or brightness; edge
  clean-up that re-measures edge alpha and unmixes the background colour
  using local foreground/background estimates; grow/shrink, despeckle,
  feather; erase/restore brush; tint, adjustments, seeded grime and edge
  wear; output sizes and power-of-two padding; colour bleed into
  transparent pixels; previews on checker, black, white, four wall
  textures and a lit 3D wall; PNG and mask export. No AI subject
  detection is claimed or used.
- Shared: `remapImage` (the palette/dither step, moved out of the
  converter with its output proven unchanged), GLB writer support for
  skins and animations, new CC0 samples in `public/demo/{models,fonts,decals}`.

**Verified**
- Unit: OKLab round trips; extraction determinism, dominant colours and
  lock handling; palette files round trip (including through real PNGs);
  atlas packing over random tile sets in every mode (no overlaps, exact
  pixels, UVs, POT/square, determinism, extrusion, padding, rotation,
  overflow, tampering caught by the validator); the rigged sample loads in
  three.js and its clip deforms the mesh; font writer/reader (checksums,
  cmap, names); BMFont round trips and renderer; charsets; decal keying,
  fringe removal measured against no clean-up, bleed, edge-touching
  subjects, strokes, morphology, background guess.
- E2E **journey 5**: four tiles edited and packed with rotation, extrusion
  and Godot UVs, exported as a ZIP and validated in Node against the
  expected tiles. **Journey 6**: rigged GLB stats and clips, play/pause/
  scrub, display modes, screenshot and report, ten loads with GPU counts
  returning exactly (a disposal mutation fails it); damaged, Draco-only and
  multi-file .gltf input. **Journey 7**: the exported .fnt + PNG render the
  sample in Node byte-identical to the preview; glyph boxes and advances
  equal the browser drawing the same font; multi-page output. Palette:
  browser extraction equals the core; every format exported and re-imported
  gives the same colours. Decal: exports equal the core byte for byte, no
  green or dark fringe, brush erase and undo, pick, POT output. axe WCAG
  2.2 AA on every tool page, empty and loaded; phone and desktop layout
  checks.

**Bugs found and fixed**: the converter's palette step needed extracting
before reuse (done with a before/after output fingerprint); the atlas re-encoded
its PNG on every change, so layout now comes first and the PNG after; the
catalogue's upload checks listed KHR_texture_basisu as viewable; scrollable
previews and lists weren't keyboard-focusable; the first decal edge clean-up
left green and dark fringes (replaced by projection against local
foreground/background estimates), and matte erosion ate subjects touching
the image edge; canvases could draw an image bitmap that had just been
replaced (guarded in the shared viewport, atlas and decal canvases); the
command palette ranked a tool whose description mentions "licensed" above the
Licences page.

**Known limitations**
- Palette: no ASE export (the plan asks for it only if it can be verified
  against Adobe apps).
- Atlas: per-tile crop is "trim transparent edges" only; no free-form crop.
- Model inspector: Draco, meshopt and KTX2/Basis aren't decoded (decoders
  aren't shipped); morph targets are counted but have no playback controls.
- Bitmap font: kerning comes from the browser's text shaping, not by
  reading kern/GPOS tables; WOFF and .ttc aren't accepted; compatibility is
  claimed only for the BMFont format as read by our renderer; no SDF/MSDF.
- Decal: crop is numeric (no drag handles) and rotation is in 90° steps.

  unapproving or deleting a creator unpublishes their videos.
- Command palette search, sitemap, landing-page highlights and JSON-LD
  (SoftwareSourceCode, VideoObject) for the new content.
- **Content**: an original PSX material for three.js (vertex snapping,

**Verified**
- Integration (PGlite and Postgres 16): every publishing rule refuses
  incomplete rows, including direct SQL; editors can't publish or approve,
  and can't edit live rows; visitors see only published rows; soft delete;
  slug format and uniqueness; shader bundle published, replaced on republish
  and removed on unpublish, with no public file left when publishing is
  refused; starter upload checks (binaries, shell scripts, non-ZIPs, wrong
  extension, another person's upload) and publish/unpublish; creator
  unapproval and deletion unpublish their videos.
- Unit: YouTube id parsing (watch, youtu.be, shorts, embed, live, rejects
  look-alikes), partial updates keep unsent fields, deterministic shader
  bundles, oEmbed handling, the shader file convention and controls.

**Bugs found and fixed**: Zod applies defaults to `.partial()` fields, so a

**Known limitations**

- Live previews exist only for three.js shaders that follow the two-stage

- No curated playlists or visitor suggestions yet (the plan lists
  suggestions as a later feature).
- YouTube Data API enrichment isn't used; oEmbed confirms a video exists and
  who published it, nothing more.

## M07 — Asset Workshop

**Built** (`/workshop`, ADR 0010)
- **Pipeline**: an ordered list of steps (crop, resize, make seamless,
  adjust colour, alpha threshold, palette, bit depth & dither, edge &
  padding) plus an optional atlas step that packs every image and always
  runs last. Steps can be added after the selected one, moved, removed,
  reset and switched off without losing their settings. Every step is a
  wrapper over the same processing core the tools use (the Seamless step runs
  the owner's engine).
- **Preview** of the original or any step for any image, compared with the
  original or the previous step (split or tiled, pixelated toggle), with
  size, colour count and timing; the atlas step previews the packed page.
  A preview worker caches intermediate results (320 MB, LRU), so changing
  one step recomputes only from there; progress and cancel.
- **Inputs**: files, folders (paths kept), drag and drop, four CC0 samples,
  and published textures from the library (licence and source recorded).
  Unreadable files are flagged and reported in the export.
- **Presets**: PSX-inspired Dirty Industrial, Pixelated Horror, N64-inspired
  Soft Palette, UI Sprite Cutout, Atlas 128 Grid (settings only, no images);
  saved recipes in this browser; JSON export/import with validation,
  defaults for missing settings, notes on what was changed, refusal of
  unknown steps and newer versions; the current pipeline is restored on the
  next visit. Images are kept only with "Keep images on this device".
- **Batch export**: PNG (deterministic encoder) or WebP, naming pattern with
  `{name}` and `{n}`, 1–4 parallel jobs, memory and size estimate before
  starting, progress and cancel, per-image failures that never discard the
  rest; ZIP with outputs (or atlas.png + atlas.json + tiles/),
  pipeline.json and manifest.json (sources with pixel SHA-256 and library
  origin, outputs with size and SHA-256, failures, atlas). The same batch
  gives the same ZIP bytes.
- `/api/workshop/library`: published, downloadable texture-like assets with
  their best PNG/JPG/WebP file.
- Docs: public R2 bucket CORS rule added to the deployment guide (the 3D
  viewer and the Workshop read published files in the browser).

**Verified**
- Unit: graph order, cycles, missing inputs, computing only what's needed,
  cache reuse, recompute after eviction, cancel; stable hashing; pipeline
  round trip, defaults and notes, refusals, atlas ordering, duplicate ids;
  each step (never mutating its input), resize targets; a Workshop pipeline
  equals the retro converter byte for byte; every preset runs
  deterministically; previews of any step, disabled steps pass through,
  editing the last step recomputes one node; export names; manifest.
- Integration (PGlite and Postgres 16): the library lists only published,
  downloadable texture-like assets with a published image file, prefers the
  primary file, filters by title.
- E2E **journey 8**: a pipeline built in the UI previews every stage,
  exports to JSON and imports back; the batch ZIP has the expected files,
  the unreadable image is reported, every output equals the core run in
  Node on the same input, every checksum holds, and a second export is
  byte-identical. Atlas preset → 512×512 page with four frames, JSON, tiles
  and manifest; recipe saved and session restored after reload; a step
  switched off and on; seamless (including mirror doubling the size) runs in
  the worker; imports explain fixes and refuse newer versions. axe on the
  empty and loaded Workshop; phone and desktop layout, including long step
  descriptions on a phone.

**Bugs found and fixed**: the atlas step rotated rotated tiles twice (the
packer's compose already turns them); a cached node evicted mid-run would
have run without its inputs (evaluation is now on demand); on a phone, long
step descriptions widened the workspace past the screen (the layout test now
checks width for every tool); the dead `/scene-builder` links in the header,
footer and home page since M01 are removed until M08 ships the page, and the
privacy page now describes exactly what the Workshop stores.

**Known limitations**
- A step list, not a visual node editor (the graph core supports one later).
- WebP needs a browser that can encode it; the Workshop says so if not.
- Inputs are limited to 8192×8192 and 128 MB each; very large batches are
  bounded by browser memory (the estimate warns above 1.5 GB).
- No cloud sync of recipes (the site has no visitor accounts).
- Model inputs aren't supported yet (no model transformation steps exist).
